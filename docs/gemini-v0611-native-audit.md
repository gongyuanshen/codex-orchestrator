## 架构优化与实测口径

- 复用现有 `workflow_prepare_dispatch` 做两件事：`accept_local` 原子注册/核对身份、建步骤、派发并接手，不生成作者收件箱或宿主动作；`submit_local_for_verify` 用原作者身份及最新修订号提交并准备真正的验收票据。准备失败时提交回滚。选择这个入口是为了沿用已有票据的断连对账协议，而不是让“作者回合”再实现一套派发账本。
- 独立验收通过且候选仍有效时，`workflow_closeout_run` 可以直接从 ready_to_merge 收尾；若内容已变，明确要求验收者重新取证。单步成功路径中协调者的**工作流准备、提交、收尾是 3 次**；不含 run、packet、板上留痕、真实宿主调用及其登记、独立验收或抽查，不声称整个任务只需三次写入。
- 比较同一口径：技能文件按 LF 规范化再取 UTF-8 字节，加默认 core 的紧凑 JSON；不计按需文档、角色指令、宿主提示、输出、协议包装或缓存。不是 token 计费数据，也不是耗时 A/B。

原报告的 32,257 B 包括 Windows 检出换行差异。22,000 B 预算已写入回归，15 KB 目标未达成。完整目录保留 37 个公开工具；常规派发和验收无需走低频网关。
- `workflow_review` 只按本 run 的实际调用身份更新工作中心跳；角色读状态时传自己的 reader_name，不凭“唯一工作中成员”猜是谁。
- 数据目录顶层未归类项按名称与字节列出，计入总量；不跟随链接或目录联接，不变成垃圾清理候选。**严格零写入调查的报告目的地是产品选择**：本次没有放宽所有权路径或擅自将报告写进运行库。

## 验证与边界

- 回归入口：`tests/test_solo_integrated_reuse.py`（真实文件、命令回执与 Stop 两端）、`tests/test_v0611_usability.py`（Solo 快捷流程、事务回滚、预算）、`tests/test_m12_native_gap_closures.py`（隔离委派流程）、`tests/test_v0611_residuals_and_liveness.py` 和 `tests/test_storage_web_ui.py`（作废、盘点、展示）。
- Windows 隔离浏览器：临时 CODEX_HOME、SQLite、项目、随机回环端口和独立浏览器 profile；无头 Edge 打开真实概况页，读到旧角色提示及“当前：作者实现”，点击存储弹窗，看到测试备份仍在盘点中，文件字节未变。最初 Chrome 的调试连接重置，不计为 Chrome 通过。浏览器验的是上述三条，不代表全部视觉界面验收。
- 一轮全量测试的隔离安装用例因 PyPI 构建依赖请求超时失败（其余 1,091 项通过、3 项跳过）；同一用例用已有 uv 缓存独立重跑通过。离线运行不绕过安装、注册、钩子信任或卸载检查。最终整套在同一缓存条件下重跑：**1,092 passed，3 skipped，346.91 秒**。跳过的是 POSIX 命名管道、POSIX 进程组和需显式指定基线与场景的真机升级演练。
- 按要求未调用活跃编排服务执行任务，未启动真实 Solo/Delegated 宿主会话做耗时 A/B，未发布或更新本机安装。没有用隔离 RPC 回归冒充线上运行。

Windows 复查：在仓库根目录用 PowerShell 设置 `$env:UV_OFFLINE="true"`（需已有依赖缓存），运行 `.venv/Scripts/python.exe -m pytest -q -rs`。
