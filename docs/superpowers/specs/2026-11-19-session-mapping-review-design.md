# 0.6.1 会话映射合入审查修复设计

目标是让 `0.6.1 / schema9 / workflow5` 在旧库升级、任务归属和实时导航上符合原交接方案。独立审查之后，用临时库已复现三种错误：新版冷启动直接迁移有活跃任务的旧库；不相关目录的轮次混入已绑定任务；新任务指定较早的 `turn_id` 却保存了最新轮次的提示词。

## 已选范围

- 新建任务的 `execution_root` 可为空、等于项目根或指向其子目录。解析后的外部目录明确拒绝，而不是接受后从另一个目录复制。嵌套任务继续使用原有项目坐标进行验收和合并。旧数据不删除、不重新绑定，既有工作区仍能从原链接查看。
- 扩展项目外执行源会改变复制来源、验收范围与合并目的地；单独设计，不在本次发布里引入。
- 只在 `G:\test` 和独立临时目录工作。保留 `HANDOFF_PROGRESS.md` 本地文件；不修改原仓库、Codex 安装配置、线上数据库或 `18790`，不提交、不推送、不发布。

## 设计与验收边界

| 边界 | 行为 |
| --- | --- |
| 冷启动与升级 | 守护进程先确认已有库已升级；旧库无论有无活跃任务都交由 `scripts/upgrade.py prepare → apply → verify`。MCP 冷启动给出可处理的提示。空数据目录可正常初始化。普通测试默认隔离 Codex 元数据，真机 T7 仍须显式提供路径，只操作副本。 |
| 历史项目 | 不能仅凭旧 `is_git` 判断是不是独立仓库；存在 `.git` 文件或目录的真实子仓库保持独立，不确定、不可用的旧仓库不猜。独立注册的 Codex 项目不被更外层的项目吸收。对有历史切片的 Codex 父项目，可新增缺失的父项目行，归并展示但不改旧 ID、根路径、旧列原值或任务所属 ID。 |
| 对话轮次 | `turn_id` 显式指定时，只从相同会话的这一轮补提示词。新任务声明触发轮次后，该轮不再因为旧任务的临时关联而出现在旧任务日志；其他续聊以 Hook 明确关联为准，不按时间猜。两个任务若明确声明同一轮，可各自展示它。会话事件仅推送用于刷新界面的标识。 |
| 控制台 | 每个新版标签页只占用一条 SSE 连接；选中任务仅消费该任务的事件，旧版保持原兼容路径。切换项目或模式时不漏掉最近 100 条之外的活跃任务；后台刷新保留列表、折叠组及命令面板的键盘焦点。区分活跃会话数和任务数，并在日志等非概况页仍能看到当前项目的并发直改提示。 |

既有 `GET /api/runs/{run_id}` 继续返回精确的 `{run, project}`；旧项目 ID 和链接仍可用；不推测旧 `session_id`、不补造历史验收或批次号。用合成夹具覆盖边界条件，再跑全量回归、独立端口 T7 和浏览器交互复验。
