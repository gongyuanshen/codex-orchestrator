# v0.6.7 发布验收：修复 v0.6.6 回归

基线为 GitHub 标签 `v0.6.6`（`448f078`）。目标版本为 `v0.6.7`，保持 schema 10 与 `workflow5` 不变。

| 验收项 | 结果 |
| --- | --- |
| Git 工作区 | 用临时仓库实测已有同名分支、分支后来被移动、Git 锁住工作区、复制未忽略的配置和依赖、派发后续步骤出错。修复后保留非本次创建的资源，拒绝不符合条件的复制或清理，派发回滚同步清理 Git 登记。默认 clone 不变。 |
| Windows 角色保护 | 用独立 `CODEX_HOME` 实测 CLI-only、旧版无角色归属记录、手工编辑后重装、`-KeepBackups 0`、还原配置、符号链接和硬链接。非插件拥有或已编辑的文件获保留，已覆盖的用户角色可从独立备份恢复。 |
| Bash 安装 | 用 Git Bash 和真实 Codex CLI 分别完成默认注册、显式信任钩子，核对安装状态和四个钩子。 |
| 首次验收与取消 | 首次验收创建缺失的父目录但不覆盖旧回执。Windows 实发 Ctrl+C 和定向 Ctrl+Break，确认待执行命令未启动、已启动子进程及其后代退出，并保留终态回执。持续拖慢心跳 HTTP 响应的探测也能在总等待期限后终止。 |
| 旧版数据升级 | 用实际 `v0.6.0`、`v0.6.1` 源码生成历史数据，离线迁移 schema 8、9 到 10。两次都保留历史任务和消息，且未改旧插件缓存；启动独立新后台后通过版本、结构和数据目录校验。隔离 Codex CLI 验证了固定标签需要更换来源，不能只刷新旧标签。 |
