## Frozen input
- Extend artifact_capture with verification_commands: nonempty list of exact command objects: id (unique nonempty string), argv (nonempty string array), cwd (absolute existing dir), timeout_sec (finite positive number), env_keys (unique environment key names; existence checked only in collector caller environment; never store values), criteria (nonempty unique strings drawn from step criteria). Collectively cover every step criterion.
- Workflow3 requires this input; workflow0/1/2 retain prior call semantics and reject unsupported extra command input rather than silently ignoring it.
- Persist manifest within descriptor.verification_manifest before artifact insertion. No new table. Write identical canonical JSON to a backend-owned manifest file outside captured artifact scope; return manifest_path and manifest_digest in artifact response. File writing must not overwrite historical artifacts. Missing/changed file is an error; do not recreate evidence on read.
- Manifest schema: schema_version:1, evidence_level:'local_collector_v1', run_id, step_id, artifact_id, scope, packet_version, attempt, contract_revision, verifier, verifier_agent_id, artifact (the capture_content result BEFORE required_paths/workspace_id/merge metadata is added), commands (validated command list).
- Canonical manifest_digest = artifacts.digest(manifest). The embedded frozen object/digest in SQLite is the trust anchor, not a newly supplied receipt hash. The content snapshot is noncircular; full workflow artifact digest includes verification_manifest.

## CLI / runner exports
- Entry point tri-orchestrator-verify = orchestrator.verify_runner:main.
- CLI: --manifest ABSOLUTE_FILE --output-dir ABSOLUTE_NEW_DIRECTORY. Collector receives no DB/HTTP execution capability. Output directory must not exist and must be outside captured artifact scope; no overwrites, no shell strings. Log/manifest files outside captured paths. Test-generated files stay outside via explicit argv/cwd/env contracts.
- Runner exports validate_manifest(manifest) returning None, collect(manifest_path:Path, output_dir:Path) returning receipt dict, validate_receipt(manifest:dict, receipt_path:Path, *, require_success:bool) returning list of evidence Path objects (receipt + all present raw logs). Validation raises ValueError with context. Integrator may request minimal refinements before implementation.
- CLI prints one bounded JSON summary containing status, receipt_path, manifest_digest (no raw output); exit0 only complete collection with all process exitcodes0. Nonzero actual test commands remain fully collected, status finished but CLI nonzero. Verifier still judges individual criteria; status finished or exit0 never creates PASS by itself.

## Receipt contract
- schema_version:1, evidence_level:'local_collector_v1', manifest_digest, status, started_at, ended_at (null while incomplete), artifact_before_digest, artifact_after_digest (nullable if unavailable), commands, error (nullable). Source checkpoint digests compare to artifacts.digest(manifest.artifact); metadata baseline is immutable.
- Command records preserve command_id, status, started_at, ended_at, exit_code (null if unavailable), stdout/stderr objects {path, bytes, sha256}; pending/running records may have null digest/byte count until captured. Absolute log paths are scoped to the output directory. Exact argv/cwd/env_keys/timeout/criteria are referenced by immutable manifest rather than rewritten. Only raw stdout/stderr bytes are logged, separated; do not dump environment mappings or serialize environment values. Command-generated output is raw, not silently rewritten/redacted.
- Write running receipt atomically BEFORE process creation; update atomically at each command boundary; on launch failure/timeout/cancel/collection failure preserve truthful incomplete status and available output, never synthesize finished. Forced collector death leaves running plus partial raw files; Windows job ownership closes the child tree.
- Finished means every frozen command ran and was captured, including nonzero exits; incomplete runs cannot PASS. require_success=True requires finished, every command in frozen order, exit0, timestamps/output hashes, pre/post current snapshot equality. require_success=False may retain explicit incomplete failure evidence, but must validate manifest identity, present command IDs/order, every recorded digest, and current present output paths; never upgrade running/incomplete into finished.
- Validation at record and at later gate use checks stored manifest identity, receipt and output digests against original registered evidence chain, binding/attempt/contract, artifact current snapshot. Record final evidence list through capture_evidence, not just receipt JSON. PASS checks all criteria explicitly and complete successful receipts. CLI JSON+SHA is local collection evidence, not host identity authentication or signature.

## Process lifetime and negative evidence
- Windows: use owned Job Object with KILL_ON_JOB_CLOSE and atomic creation-to-job assignment (STARTUPINFOEX JOB_LIST), explicit inherited output handles only. No PID/name sweep. Reject unsupported ownership APIs clearly. On timeout/cancel terminate owned job, confirm zero active children, otherwise mark cleanup failure. Research notes in m2-process-report.md.
- Source snapshot checkpoints: before/after collection and at workflow gates. Temporary mutation followed by exact restoration between checkpoints remains intentionally undetectable; actual test documents limitation, not prevented attack.
- All implementation tests start RED, actual subprocess cases include missing executable/nonzero/unicode+spaces/big separate outputs/timeout/child-cancel/forced collector kill/receipt mutation/old attempt/source mutation. No mocked success. External isolated temp dirs.

## Revision 1 clarifications
- env_keys is the exact child environment allowlist. The daemon validates only key syntax/uniqueness; the collector checks required values exist. Values are never copied into JSON. Raw program output is intentionally unchanged, including if a program itself prints a secret.
- Existing summary artifacts add only evidence_level and verification_command_count; this means a frozen collection contract, not proof of a successful collection or authenticated host.
- POSIX standard process-group cleanup is supplemental compatibility; Windows Job lifetime behavior is the acceptance platform and guarantee. Report non-Windows runtime verification separately.
