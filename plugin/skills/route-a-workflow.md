# Route A structured workflow (`workflow5` in `0.6.6/schema10`)

Load this shared contract before running Boost, Teamwork, or Swarm. New runs default to `workflow5` (`0.6.6/schema10`; unknown versions are unsupported and no public downgrade selector exists). Stored `workflow0..4` runs in existing databases continue strictly by `board_status.workflow.workflow_version` without fabricated historical evidence (`workflow0` legacy, `workflow1` foundation, `workflow2` mode bindings, `workflow3` local collector, `workflow4` admission/handoff/grouped actions; `workflow1..4` bootstrap children remain waiting-only until admission and persisted delivery). Never use raw SQL, metadata, worker status, or a board PASS to disable gates. A receipt is not independent acceptance.

## 1. Run initialization & frozen task packet

1. Always pass the current Codex root session ID to `run_create` (`session_id=$env:CODEX_THREAD_ID` in PowerShell; use the hook-reported root ID if unavailable). Never substitute a worker ID, infer it from a path, or reuse another session's ID. `workflow_prepare_dispatch` can also carry the same `session_id` to bind lifecycle hooks (`session_run_bindings`).
2. Pass the real workspace or repository root as `project_root`; pass a staging/slice subdirectory separately as `execution_root` (omit if unused). Do not register a slice as a new `project_name`. `run_create` and `board_status(compact=True)` also return `cli_executables` (`verify` and `challenge` resolved directly from the active plugin `.venv`).
3. Freeze the verbatim requirement, `file_ownership`, and nonempty unique string `acceptance_criteria` with `task_packet_save`.

## 2. Plan admission, step contracts & `execution_kind`

1. Create work items with `workflow_step_save(run_id, step_key, owner, verifier, workspace_id when used, dependencies, criteria)` covering all frozen packet criteria without weakening checks, keeping step `id` and `expected_revision` from fresh stored state. Author and verifier must be a different native agent, not merely different names; Solo uses the coordinator as author and a separate native verifier.
2. Inspect read-only `plan_readiness` (hints only; draft steps allowed) before atomic admission, which rejects concurrent Windows case, glob, containment, and path-alias overlaps. Sequential same-file reuse requires explicit dependency, predecessor final PASS from the original verifier, confirmed handoff, and real native quiescence at first admission; merge-chain proofs govern post-merge repairs, and affected steps reopen via `action="reverify"` before completion or `needs_decision`.
3. Freeze `execution_kind="native"` (default for interactive modes) or `execution_kind="coordinator_local"` via `workflow_step_save` before first dispatch. `coordinator_local` is allowed only for Boost without a workspace (`workflow4`/`workflow5`, immutable after `original_bindings`), recording `coordinator_local_boundaries` with completed synchronous local edit/verification phase evidence—never claim root host idle while running, and honor all `stopped`/`ended`/packet/binding/budget checks.
4. Revise executed local steps only via single-use `action="local_revision_boundary"` bound to `revision/packet/contract/attempt` and project content `content_digest` (`local_revision_boundaries` history); any intervening observation or filesystem edit invalidates it. `task_packet_save` consumes the boundary, requiring a fresh `local_revision_boundary` before `workflow_step_save` for each executed local step (including after removing an old criterion).

## 3. Codex V2 subagent rules & `max_depth = 2` helpers

- **Model inheritance & autonomous `reasoning_effort` selection**: NEVER pass a hardcoded `model` parameter on `spawn_agent`—always omit `model` so 100% of subagents inherit the active Codex session model. For `reasoning_effort`, the coordinator autonomously selects the appropriate tier (`low`, `medium`, `high`, or `ultra`) on `spawn_agent` based on the subagent's task difficulty (or omits `reasoning_effort` to inherit the session tier).
- **Zero-script `agent_type` omission**: When `~/.codex/agents/*.toml` custom agent TOMLs are absent, **omit `agent_type` entirely** (do NOT pass a fallback `"default"` role name, because `codex.exe` omits `agent_type` from `spawn_agent`'s `additionalProperties: false` schema when custom agents are absent) and inline the matching role contract in `message`.
- **Nuanced `fork_turns` policy**: In Codex V2, custom `agent_type` applies regardless of `fork_turns`. Keep `fork_turns: "none"` to keep child context minimal and for unbiased blind `verifier` and `challenger` review; allow `fork_turns: "all"` when coordinator context is already warm and `coder`/`swarm_worker`/scoped `investigator` needs no context isolation.
- **Controlled `max_depth = 2` helpers**: `interviewer`, `investigator`, and `challenger` are strictly forbidden from spawning subagents. Depth-1 `planner`, `coder`, `swarm_worker`, and `verifier` MAY spawn pure read-only `investigator` helpers within active concurrency budget for cross-module call-chain lookup ONLY (helpers never edit files, never register as author/verifier on `18790`, and never submit verification receipts; caller remains solely accountable).

## 4. Dispatch, native transfer ledger & reconciliation

1. **Primary `workflow5` 1-turn direct dispatch & lazy `verifier`**:
   - For a new author, call `workflow_prepare_dispatch(run_id=..., step_key=..., owner=..., verifier=..., recipient=..., role=..., task_name="<task_name>", verifier_task_name=..., dispatch_action="dispatch", ...)` with deterministic `task_name` (`^[a-z0-9_-]{1,48}$`, unique per run, pre-freezing `/root/<task_name>`) to atomically execute optional workspace creation (`create_workspace=True`, rolling back DB and deleting any newly created empty workspace dir on failure), `worker_register(status="waiting", task_name=...)`, `workflow_step_save`, `workflow_step_advance`, `inbox_send`, and `native_action_update` (`claim` + `begin`).
   - Issue a single direct top-level `spawn_agent(task_name="<task_name>", message="<full contract + workspace + step_id + message_id>")` — **zero waiting-only bootstrap empty turns in `workflow5`**.
   - Immediately call `native_action_record_call(run_id=..., action_id=..., claim_token=..., expected_revision=..., outcome="confirmed"|"failed", raw_response=..., agent_id=...)`: the server atomically writes the receipt JSON under `receipts/<run_id>/`, computes the 64-hex lowercase SHA-256 `evidence_digest` and `evidence_ref`, verifies `/root/<task_name>`, backfills `workers.agent_id`, `workflow_steps.owner_agent_id`, and `inbox_messages.recipient_agent_id`, freezes `checkpoint.original_bindings`, and marks the worker `working`.
   - Register `verifier` logically at step creation (`verifier_agent_id=""`, optional `verifier_task_name`; multi-slice Swarm runs may bind distinct verifiers such as `verifier_1`, `verifier_2`, ... per step for parallel candidate verification) without pre-spawning during coding. On first candidate `submit`, dispatch candidate review via `workflow_prepare_dispatch(..., dispatch_action="request_verify", recipient=verifier, task_name="<verifier_task_name>")` + 1-turn direct `spawn_agent` on `/root/<verifier_task_name>` + `native_action_record_call`; binding enforces `verifier_agent_id != owner_agent_id` and freezes `original_bindings` so all rework re-checks and integrated gates for that step reuse that exact `verifier` via `followup_task` (rebinding is rejected).
2. **Disconnect/timeout fence (`needs_reconciliation`)**:
   - Lease expiry, restart, disconnect, or lost results after `begin` fence into `needs_reconciliation` and lock the step/workspace. **Never re-claim or automatically replay an unknown action** (this is not exactly-once execution).
   - For `spawn_agent`, call native `list_agents(path_prefix="/root/<task_name>")` first, then pass observed host state to `native_action_update(action="reconcile", ...)` or `native_action_record_call(..., reconcile=True)`: if `/root/<task_name>` exists, bind that real `agent_id` with `outcome="confirmed"`; **ONLY** when `list_agents` proves `not_found` (or `spawn_agent` synchronously returned explicit rejection) may you pass `outcome="not_called"|"rejected", cancel=True` to release the lease and re-dispatch (`unknown` stays fenced).
### Manual primitive transfer ledger & grouped transfers

For fallback, controls, human guidance, or stored `workflow1..4` runs (where admission precedes native implementation dispatch):

1. Persist admitted business work with `inbox_send` using a stable key and `step_id` before waking the original author or original verifier (at most 3 automatic rework rounds).
2. Query `board_status(compact=True)` to inspect `next_actions`, `needs_reconciliation`, `needs_clarification`, and pending controls before business wakeups.
3. Call `native_action_update(action="claim")` with `run_id`, `source_type` (`inbox|control|human`), `source_id`, `recipient`, `action_type` (`spawn_agent|followup_task|send_message|interrupt_agent`), and `source_digest` to obtain `action_id`, `claim_token`, lease deadline, and revision.
4. Call `native_action_update(action="begin")` with `action_id`, `claim_token`, and `expected_revision` right before invocation; stop if claim/begin fails.
5. Make the actual native call (`spawn_agent` for `workflow5` first turn, `followup_task` for idle/ended children, `send_message` for working children, `interrupt_agent` for controls). The daemon never invokes the host.
6. Call `native_action_record_call` or `native_action_update(action="record")` with `action_id`, `claim_token`, `expected_revision`, `outcome` (`confirmed|failed|not_called|rejected|unknown`), `evidence_ref`, lowercase SHA-256 `evidence_digest`, and nonblank `result`. Note that inbox ACK, business PASS, and control ACK are separate; `worker_control_ack` is still required after interruption.

- Controls use `control_request_id`; human guidance preserves `original seq` and verbatim text, leaving ambiguous recipients in `needs_clarification` without broadcast.
- Grouped transfers (`workflow4`/`workflow5`): inspect `board_status.next_action_groups` (handle controls first; no notice-only wakeups), claim a shared recipient/binding/action_type batch via `native_action_update(action="claim_group", run_id=..., recipient=..., action_type=..., members=[{source_type,source_id,source_digest},...])` with complete group membership, call `action="begin_group"` with full member `action_id`/`expected_revision`/`claim_token`, invoke one native wake, and record via `native_action_record_call(group_id=..., members=...)` or `action="record_group"`. One expired member fences all into `native_action_groups` (`frozen_member_ids`), resolved via `action="reconcile_group"` without replay.

## 5. Author turn, controls, polling & direct MCP discipline

- **Author bounded receive & macro turn**: At most one `inbox_wait` per turn (`default 20000ms`, `max 25000ms`); return on timeout without polling loops, and check `isError`, `recipient_agent_id`, `step_id`, and `requires_reconciliation` before acting. Use `workflow_author_turn(run_id=..., step_id=..., message_id=..., phase="accept", evidence=...)` on initial dispatch (`inbox_ack("accepted")` + `accept` + `working` + heartbeat) and `workflow_author_turn(..., phase="submit", summary=..., body_md=..., post_board_note=True)` after real post-edit tests on owned files (`submit` + `inbox_ack("completed")` + optional `#verify` note + `waiting`, eliminating duplicate `board_post`). On rework (`action="start_rework"`), fix defects, re-test, and submit again without re-running raw `workflow_step_advance(action="accept")`. Keep one in-flight business wake per recipient and per-message `inbox_ack`.
- **Coordinator polling & state observation**: Pair `wait_agent(timeout_ms=30000)` max wait interval with `board_status(run_id=..., compact=True)` before and after waits so Web UI pause/stop (`control_requests`) responds within `<=30s` while avoiding body duplication (fetch full bodies on demand via `inbox_get` / `board_read`). Honor pending controls first; never auto-resume paused or killed workers. Use `action="observe"` only with real native `observation={agent_id, state, observed_at, evidence}` (observations older than 30s are stale; heartbeat expiry is not host telemetry or death). Classifier states (`ready|completed|inactive|normal_wait|dependency_wait|user_decision|needs_reconciliation|host_unknown|no_progress`) distinguish normal waiting from actionable blockers.
- **Parallel direct MCP & write discipline**: Issue independent read-only workspace checks (`workspace_status`, `workspace_diff`, `workspace_merge_preview`) as **parallel direct MCP tool calls** in the same assistant turn. Always invoke `collaboration.*` tools as top-level direct calls, check `isError` on every write tool, and abort immediately on error—**automatic retries on write tools are strictly forbidden**. For `delivery: "file"`, inspect `result_file` (`bytes`/`sha256`) locally via bounded reads.

## 6. Routing, verification collector, challenge & review gates

1. **Evidence-based routing**: Investigate only substantive unknowns, post `route_decision` (`msg_type="info"`), and add no extra author for known local fixes. Pure investigation uses the Solo report contract without invented edits or merges.
2. **Local verification collector (`local_collector_v1`, `workflow3`..`workflow5`)**:
   - Before running checks, the original verifier calls `workflow_verifier_turn(run_id=..., step_id=..., phase="prepare", scope="candidate"|"integrated", ...)` or `artifact_capture` with nonempty `verification_commands` (`id`, exact `argv`, `cwd`, `timeout_sec`, `env_keys` or `env_profile="windows_minimal_py"|"posix_minimal_py"`, optional `parallel_group` plus optional manifest `max_parallel`, `message_id=...`, and `criteria` covering each criterion). `env_keys` is the exact child environment allowlist (use `env_profile` or list `SystemRoot/PATH/TEMP` explicitly): values come from the verifier terminal, the daemon validates only key syntax/uniqueness, and environment values are never logged or serialized. Keep `manifest_path`, `manifest_digest`, and logs outside captured source, and capture `candidate` and `integrated` separately (`prepare` / `artifact_capture` return `verify_executable` and `verify_command_hint` with `--heartbeat-url` keepalive from `cli_executables`).
   - Run `tri-orchestrator-verify --manifest ABS --output-dir NEW_ABS` in the host terminal via returned `verify_executable` (no arbitrary command RPC exists; high-complexity adversarial checks may also run host `tri-orchestrator-challenge` from `cli_executables`).
   - Call `workflow_verifier_turn(phase="record", ...)` (or `verification_record` with real `receipt_files`, per-criterion `PASS/FAIL/NOT_RUN`, explicit `inbox_ack` `accepted` -> `completed`, and Boost candidate `action="challenge"` bound to `artifact_id=candidate["id"]` when calling primitives directly). Note that raw stdout/stderr may hold command-origin secrets while environment values stay unlogged; `local_collector_v1` is local collection, not host authentication, and cannot detect temporary modification restored between checkpoints.
3. **High-complexity review & challenger findings**:
   - High-complexity steps (`complexity="high"`) allow an independent read-only challenger (or host `tri-orchestrator-challenge`) to map counterexamples via `workflow_review(step_id, expected_revision, agent_id, criterion, evidence)` to an existing acceptance criterion on the same failed step.
   - Original `verification_record` requires `review_dimensions` (`specification`, `code`, `stress`, `evidence` as `PASS|FAIL|NOT_RUN`, with all four `PASS` required on `complexity="high"`; optional on normal complexity).
   - Original verifier records `FAIL` and original author repairs within at most 3 automatic rework rounds (then `needs_decision`; genuinely new requirements need explicit packet revision, and only new independent scope gets a new step). Substantiated `FAIL` repairs resolve via `resolved_finding_ids` on later `PASS`; only original-verifier actual `PASS` may dismiss unsubstantiated items via `dismissed_finding_ids` without increasing attempt (a substantiated `FAIL` cannot be dismissed).

## 7. Mode sequencing, handoff, merge & closeout

- **Boost**: execute -> capture candidate -> independent challenge (`artifact_id=candidate["id"]`) -> candidate verify -> original-author repair on `FAIL` -> same-verifier re-verify (max 3 automatic rework rounds, then `needs_decision`) -> merge (`workspace_merge_preview` -> `workspace_merge`, or Solo `action="begin_integrated_review"`) -> separate integrated gate.
- **Teamwork & Handoff**: each milestone step requires predecessor integrated `PASS` and confirmed handoff (`action="handoff"`, `recipient_agent_id=next_coordinator_agent_id`, `next_responsibility`, `forbidden_actions`, `decision_seqs` -> `handoff_history`, confirmed by intended recipient via `action="ack_handoff"` with exact `handoff_digest`; single-root Teamwork may set `handoff_required=False`; ordinary notices do not invalidate packs; resume via read-only `resume_context`) before dependent admission; root retains child lifecycle ownership.
- **Swarm**: `inbox_send` kinds `task/rework/review/result` bind `step_id` and recipient; at most one `inbox_wait` (`20000ms..25000ms`) per worker turn, and verify real native state before waking idle children.
- **Merge recovery & post-merge reverify**: never replay uncertain writes blindly; interrupted merges enter `reconciliation_required` (`workspace_merge(reconcile=True)`). Use `action="reverify"` if later merges touch approved scope.
- **Storage transparency & 1-call closeout**: When provisioning `create_workspace=True` on non-Git roots (`mode="snapshot"`), watch `TRI_ORCH_MAX_SNAPSHOT_MB` (default `500` MB) and exclude large/generated trees via `.triignore`. After all `scope="integrated"` gates pass, call `workflow_closeout_run(run_id=...)` to atomically complete `integrated_review` steps, run guarded `workspace_cleanup`, mark workers `stopped`, and execute `run_update(status="completed")` in **1 MCP call**; explicitly report in the final user response whether isolated workspaces were cleaned and whether any unmerged/dirty leftovers remain.
