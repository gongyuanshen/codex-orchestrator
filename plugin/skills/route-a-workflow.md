Load this shared contract before executing Boost, Teamwork, Swarm, or `$pipeline` (`tri-orchestrator-pipeline`). In software 0.6.0/schema8, new runs default to `workflow5` (superseding the M3/M4/M5 software 0.5.0/schema7 baseline where New runs use workflow4). Unknown versions are unsupported; no public downgrade selector. Never use raw SQL, metadata, worker status or a board PASS to disable gates. A receipt is not independent acceptance.

2. Create work items with workflow_step_save(run_id,step_key,owner,verifier,workspace_id when used,dependencies,criteria) covering all frozen packet criteria without weakening checks. Keep step id and expected_revision from fresh stored state.
3. ## M1 native transfer ledger

Software 0.4.0/schema6 added the M1 ledger (`workflow0/1/2 semantics remain unchanged`; `workflow3` business collector gates are in M2 below). In `workflow5`, `workflow_prepare_dispatch` + `native_action_record_call` encapsulate steps 1, 3, 4, and 6 atomically; stored `workflow1..4` bootstrap children remain waiting-only until admission and persisted delivery:

1. Persist admitted business work with inbox_send using a stable work-item/attempt key and step_id before waking the original author or original verifier (max 3 automatic rework rounds).
2. Query board_status (`compact=True` recommended) to inspect read-only next_actions, needs_reconciliation, needs_clarification, and pending controls before business wakeups.
3. Call native_action_update(action="claim") with projected run_id, source_type (`inbox|control|human`), source_id, recipient, action_type (`spawn_agent|followup_task|send_message|interrupt_agent`), and source_digest to obtain action_id, claim_token, lease deadline, and revision.
4. Call native_action_update(action="begin") with action_id, claim_token, and expected_revision right before invocation; stop if claim/begin fails.
5. Make the actual native call against the target (`spawn_agent` for `workflow5` first turn, `followup_task` for idle/ended, `send_message` for working, `interrupt_agent` for controls). The daemon never invokes the host.
6. Call `native_action_record_call` or `native_action_update(action="record")` with action_id, claim_token, expected_revision, outcome (`confirmed|failed|not_called|rejected|unknown`), evidence_ref, lowercase SHA256 evidence_digest, and nonblank result. Note that inbox ACK, business PASS and control ACK are separate; `worker_control_ack` is still required after interruption.

Lease expiry, restart, disconnect, or lost results after `begin` fence into `needs_reconciliation`: never automatically replay an unknown action (SQLite and host are not assessments of not exactly-once execution). Call `native_action_update(action="reconcile")` with current `action_id`/`expected_revision` and real host evidence (for `spawn_agent`, query `list_agents(path_prefix="/root/<task_name>")` first). Only evidenced `not_called` or `rejected` permits retry or `cancel=true`; `unknown` stays fenced. Controls use `control_request_id`; human guidance preserves `original seq` and verbatim text, leaving ambiguous recipients in `needs_clarification` without broadcast.

## M5 grouped transfer and global stall contract

For `workflow4` and `workflow5`, inspect `board_status.next_action_groups` (handle controls first; no notice-only wakeups). - Check `isError`, `recipient_agent_id`, `step_id`, and `requires_reconciliation` before acting.
- Prefer single-transaction `workflow_author_turn(phase="accept")` on initial dispatch (atomically running `inbox_ack(status="accepted")` + `action="accept"` + setting `status="working"` + heartbeat) and `workflow_author_turn(phase="submit", summary=..., body_md=..., post_board_note=True)` after real post-edit tests on owned files (atomically running `action="submit"` + `inbox_ack(status="completed")` + optional `#verify` note + resetting `status="waiting"`). - Inspect read-only `plan_readiness` (draft steps allowed) before atomic admission, which rejects concurrent Windows case, glob, containment, and path aliases overlaps. - Compact handoffs (`action="handoff"` with `next_responsibility`, `forbidden_actions`, `decision_seqs` -> `handoff_history`) require the intended recipient's `action="ack_handoff"` with exact `handoff_digest` (ordinary notices do not invalidate packs). Resume via read-only `resume_context`.

Substantiated FAIL repairs resolve via `resolved_finding_ids` on later PASS; only original-verifier actual PASS may dismiss unsubstantiated items via `dismissed_finding_ids` without increasing attempt (`substantiated FAIL cannot be dismissed`).

## M4 evidence-based routing and counterexamples

Investigate only substantive unknowns, post `route_decision` (`msg_type="info"`), and add no extra author for known local fixes; static contracts alone prove instructions, as a static check does not prove routing quality. For difficult scope, a clean-context read-only challenger (or host `tri-orchestrator-challenge`) maps counterexamples via `workflow_review` to an existing acceptance criterion on the same failed step; the original verifier records FAIL and the original author repairs within the remaining 3 automatic rework rounds (genuinely new requirement needs explicit packet revision; only new independent scope gets a new step). Pure investigation uses the Solo report contract without invented edits or merges.

## Verifier: version-bound candidate and integrated gates

1. Inspect packet, step, and diff; call `workflow_verifier_turn(phase="prepare", scope="candidate", ...)` (or `inbox_ack(status="accepted")` + `artifact_capture(step_id, scope="candidate")`) before running verification commands via `verify_executable`. Boost challenge binds `action="challenge"` to `artifact_id=candidate["id"]` (handled atomically by `workflow_verifier_turn(phase="record")`).
2. Record `workflow_verifier_turn(phase="record", ...)` (or `verification_record` + `inbox_ack(status="completed")`) with per-criterion `PASS/FAIL/NOT_RUN`, real `receipt_files`, and retained evidence without editing code.
3. After candidate PASS, merge (`workspace_merge_preview` -> `workspace_merge`, or Solo `action="begin_integrated_review"`), capture `scope="integrated"` before running main-directory tests, record integrated PASS, and finish via `workflow_closeout_run(run_id=...)` (or manual `action="complete"` + `workspace_cleanup` + worker `stopped` + `run_update(status="completed")`; use `action="reverify"` if later merges touch approved scope).

## Failure, controls and recovery

- Maximum 3 automatic rework rounds after initial failure, then `needs_decision`. Never replay uncertain writes blindly; interrupted merges enter `reconciliation_required` (`workspace_merge(reconcile=True)`). Check `board_status(compact=True)` before/after `wait_agent(timeout_ms=30000)`; native observations older than 30s are stale.

## Mode2 sequencing and delivery binding

- **Boost**: execute -> capture candidate -> independent challenge -> candidate verify -> original-author repair on FAIL -> same-verifier re-verify -> separate integrated gate.
- **Teamwork & Handoff**: each milestone step requires predecessor integrated PASS and confirmed handoff (`action="handoff"`, `recipient_agent_id=next_coordinator_agent_id` -> `action="ack_handoff"` with `handoff_digest`) before dependent admission; root retains child lifecycle ownership.
- **Swarm**: `inbox_send` kinds `task/rework/review/result` bind `step_id` and recipient; at most one `inbox_wait` (`20000ms..25000ms`) per worker turn, and verify real native state before waking idle children.
