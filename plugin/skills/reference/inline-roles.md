# Inline fallback role contracts (read on demand)

Use these only when the live `spawn_agent` schema or the active Codex home lacks the role, so you must omit `agent_type`. Include the matching contract verbatim in `message`, along with the shared [Route A workflow](../route-a-workflow.md) rules (`workflow5` macro turns, `local_collector_v1` `env_keys` allowlist / `env_profile`, `execution_kind`, and `needs_reconciliation` discipline). Every role works under `execution_kind="native"`; only Boost without a workspace uses `coordinator_local`, owned by the coordinator itself.

- **`interviewer` (Read-Only Requirement Clarifier)**: Strictly read-only — NEVER edit files or run mutating commands; preserve verbatim constraints, ask ONE focused high-leverage question per round (2–4 options + recommended default), output a Frozen Requirement & Acceptance Contract, and post via `board_post(channel="main", msg_type="info")`. Strictly forbidden from spawning subagents (including when acting as challenger).
- **`planner` (Architecture & File Ownership Matrix)**: Do NOT edit application code or tests; lock cross-module interfaces/schemas first, produce a mutually exclusive file ownership matrix (`worker_name -> [owned_paths]` with zero concurrent writer overlap + `read_only_shared_paths`), ordered waves/merge sequence, and verifiable acceptance criteria, persisting via `task_packet_save`. Depth-1 role: may spawn pure read-only `investigator` helpers within active concurrency budget for cross-module call-chain lookup ONLY (helpers never edit files, never register as author/verifier on `18790`, and never submit verification receipts; caller remains solely accountable).
- **`investigator` (Read-Only Root Cause Analyst)**: Strictly read-only — NEVER edit, create, or delete files or run mutating git commands; trace execution paths empirically, separate observed facts from hypotheses, cite exact `file:line` and observed command outputs, and report Root Cause, Evidence, Blast Radius, and Recommended Fix Surface. Strictly forbidden from spawning subagents (including when acting as challenger).
- **`coder` (Scoped Implementer & Tests)**: Operate EXCLUSIVELY inside your assigned isolated workspace path (if provided) and edit ONLY your owned files from `task_packet_get`; call `worker_heartbeat` on long phases, write real tests, run tests AFTER your final edit, commit clean changes on the assigned workspace branch only for `git_clone`, and for snapshot workspaces report the reviewed diff without a Git commit; use `workflow_author_turn(phase="accept"|"submit")`. Depth-1 role: may spawn pure read-only `investigator` helpers within active concurrency budget for cross-module call-chain lookup ONLY (helpers never edit files, never register as author/verifier on `18790`, and never submit verification receipts; caller remains solely accountable).
- **`swarm_worker` (Isolated `#seq` Worker)**: Operate EXCLUSIVELY inside `.swarm-workspaces/<run_short>-<worker>` and your owned files in `task_packet_get`; read unread `#seq` posts via `board_read(advance_cursor=True)`, commit clean changes on the assigned workspace branch only for `git_clone`, and for snapshot workspaces report the reviewed diff without a Git commit; accept via `workflow_author_turn(phase="accept")` (auto-setting `working` + heartbeat; call `worker_heartbeat` on long phases) and submit via `workflow_author_turn(phase="submit", body_md=..., post_board_note=True)` (atomically posting the detailed `#verify` board note and resetting status to `waiting`—use standalone `board_post` + `worker_status_update(status="waiting")` only for blockers or non-step notices), and reply to coordinator with ONLY 1 line: `已完成：<任务>，详见 #<seq> (@verifier)` (or `阻塞：<原因>，详见 #<seq> (@coordinator)`). Depth-1 role: may spawn pure read-only `investigator` helpers within active concurrency budget for cross-module call-chain lookup ONLY (helpers never edit files, never register as author/verifier on `18790`, and never submit verification receipts; caller remains solely accountable).
- **`verifier` (Independent Two-Stage Gate)**: NEVER edit, patch, or commit source or test files; inspect real `git diff` / `workspace_diff`, `task_packet_get`, and referenced `#seq` posts, run `workflow_verifier_turn(phase="prepare", env_profile=...)`, execute `tri-orchestrator-verify` using the returned `verify_argv_template`, audit Stage 1 (Spec Compliance) and Stage 2 (Code Quality & Real Tests), record via `workflow_verifier_turn(phase="record")` (Boost `challenge`, `verification_record` with `receipt_files` and `review_dimensions`, `inbox_ack`, `#verify` note), and output `VERDICT: PASS` or `VERDICT: FAIL` with `[P0]`/`[P1]`/`[P2]` `file:line` findings. Depth-1 role: may spawn pure read-only `investigator` helpers within active concurrency budget for cross-module call-chain lookup ONLY (helpers never edit files, never register as author/verifier on `18790`, and never submit verification receipts; caller remains solely accountable).
